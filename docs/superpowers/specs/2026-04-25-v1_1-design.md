# sensmaps v1.1 — design

Author: Giles Blaney (with Claude Code)
Date: 2026-04-25
Status: brainstorm output, awaiting user spec review

## 1. Purpose

Extend the MATLAB-compendium parity surface from the single `CW_SD_I`
combo (v1) to the full set of CW + FD measurement types under diffusion
theory, and introduce the source / detector arrangement combinators
(`SS`, `DS`) used by all of TD as well. v1.1 is the first of three
stepwise minor releases on the way to v2.0 (full MATLAB parity for
DT, see §8). Time-domain types and the `SD_DIFF` combinator stay out
of scope until v1.2 / v1.3.

### 3.2 Physics layer (no changes)

Per v1's spec §8, the `complex_*` building blocks were ported in v1

```
src/sensmaps/physics.py

```

No new functions; no MATLAB-fidelity audit needed for the physics
layer in v1.1.

### 3.3 Compute layer (the main work)

Three additions to `src/sensmaps/compute.py`:

#### 3.3.1 Per-measurement physics dispatch

A module-level table keyed on `(temporal, data_type)` returning
three callables — `(L_fn, ll_fn, Y_fn)` — applied per measurement
row `(rSrcs[i], rDets[i])`:

```python
_PHYSICS_DISPATCH: dict[tuple[str, str], tuple[Callable, Callable, Callable]] = {
    ("CW", "I"): (
        lambda rs_i, rd_i, op, **_:
            continuous_tot_path_len(rs_i, rd_i, op)[0][0],
        lambda rs_i, r, rd_i, V, op, **_:
            continuous_part_path_len(rs_i, r, rd_i, V, op),
        lambda *_a, **_kw: 1.0,
    ),
    ("FD", "I"): (
        lambda rs_i, rd_i, op, fmod, **_:
            complex_tot_path_len(rs_i, rd_i, 2*np.pi*fmod, op)[0][0].real,
        lambda rs_i, r, rd_i, V, op, fmod, **_:
            complex_part_path_len(rs_i, r, rd_i, V, 2*np.pi*fmod, op).real,
        lambda *_a, **_kw: 1.0,
    ),
    ("FD", "P"): (
        lambda rs_i, rd_i, op, fmod, **_:
            complex_tot_path_len(rs_i, rd_i, 2*np.pi*fmod, op)[0][0].imag,
        lambda rs_i, r, rd_i, V, op, fmod, **_:
            complex_part_path_len(rs_i, r, rd_i, V, 2*np.pi*fmod, op).imag,
        lambda *_a, **_kw: 1.0,
    ),
}
```

Lookup: `(L_fn, ll_fn, Y_fn) = _PHYSICS_DISPATCH[(temporal, data_type)]`.
Missing pair → `NotImplementedError(f"type_str={type_str!r} is not implemented in v1.1")`.

#### 3.3.2 Optode-expansion helper

A pure helper `_expand_optodes(arrangement, rs, rd, z_offset) -> (rSrcs, rDets)`
that mirrors MATLAB `makeS.m` lines 123–149:

| arrangement | accepted shapes                                    | output rows |
|-------------|----------------------------------------------------|-------------|
| `SD`        | `rs (1,3)`, `rd (1,3)`                             | 1           |
| `SS`        | `rs (1,3)+rd (2,3)` **or** `rs (2,3)+rd (1,3)`     | 2           |
| `DS`        | `rs (2,3)`, `rd (2,3)`                             | 4           |

DS row pattern (per MATLAB): `rSrcs = [rs1; rs1; rs2; rs2]`,
`rDets = [rd1; rd2; rd2; rd1]` (the `flipud` half).

Bad shapes raise `ValueError(f"Incorrect optode count for arrangement {arrangement!r}: ...")`
naming the arrangement and the offending shapes.

The `+ z_offset` along z is applied inside this helper, on `rSrcs`
only (matches MATLAB's `[0, 0, z0]` add).

#### 3.3.3 Arrangement combinators

Direct port of MATLAB `makeS.m` lines 397–411, three small functions:

```python
def _combine_sd(L, Y, ll):
    return ll[0] / L[0]

def _combine_ss(L, Y, ll):
    return (Y[1]*ll[1] - Y[0]*ll[0]) / (Y[1]*L[1] - Y[0]*L[0])

def _combine_ds(L, Y, ll):
    num = (Y[1]*ll[1] - Y[0]*ll[0]) + (Y[3]*ll[3] - Y[2]*ll[2])
    den = (Y[1]*L[1]  - Y[0]*L[0])  + (Y[3]*L[3]  - Y[2]*L[2])
    return num / den
```

Picked by `_ARRANGEMENT_COMBINE = {"SD": _combine_sd, "SS": _combine_ss, "DS": _combine_ds}`.
`SD_DIFF` is **not** added in v1.1 (lands with TD DGI in v1.3).

#### 3.3.4 `make_s_full` signature

```python
def make_s_full(
    type_str, rs, rd, opt_prop,
    xl, yl, zl, dr,
    pert=(1.0, 1.0, 1.0),
    sim_typ="DT",
    *,
    fmod=None,                        # Hz; required for FD_*; ignored otherwise
) -> SensitivityResult:
```

`make_s` thin wrapper unchanged in spirit — accepts the same kwargs
and returns `(S, params)`.

**Validation order inside `make_s_full`:**
1. `parse_type_str` (existing).
2. If `parsed.temporal == "FD"` and `fmod is None` →
   `ValueError("fmod is required for FD_* types")`.
3. `_expand_optodes(arrangement, rs, rd, 1/opt_prop.musp)` — raises
   on shape mismatch (existing v1 implicit `(1,3)` check moves into
   this helper).
4. Pert-multiple-of-dr check (existing).
5. Per-measurement physics loop: builds three length-`N_meas` lists
   - `L: list[float]` (one path-length scalar per measurement),
   - `Y: list[float]` (one measured-signal scalar per measurement; 1.0 for v1.1),
   - `ll: list[np.ndarray]` (each shape `(Nx, Ny, Nz)`, NaN→0).
6. Arrangement combinator (§3.3.3) consumes those lists by index
   (`L[0]`, `ll[1]`, etc.) → `Svox: (Nx, Ny, Nz)`.
7. `apply_pert_kernel` (existing helper).
8. Return `SensitivityResult` (with `Y_per_meas = np.asarray(Y)`).

#### 3.3.5 `SensitivityResult` adds two fields

```python
from dataclasses import dataclass, field

@dataclass
class SensitivityResult:
    S: np.ndarray
    Svox: np.ndarray
    params: GridParams
    type_str: str
    rs: np.ndarray
    rd: np.ndarray
    opt_prop: OpticalProperties
    pert: tuple[float, float, float]
    dr: float
    # NEW — kw-only so existing positional construction (if any) keeps working:
    Y_per_meas: np.ndarray = field(kw_only=True)
    fmod: float | None = field(default=None, kw_only=True)
```

`Y_per_meas` is shape `(N_meas,)` and is always `np.ones(N_meas)`
for v1.1's combos; the field is plumbed so v1.3's `T` / `V` types
work without re-shaping the dataclass. `fmod` is the modulation
frequency in Hz (or `None` for CW); used by `save_data` and by
display code that wants to show the FD frequency.

### 3.4 Views layer (no changes)

`render_slice` already plots multi-row `rs` / `rd` (post-fix #2,
optodes are filtered to the slice plane regardless of count).
Nothing to do.

### 3.5 GUI layer

#### 3.5.1 Type combobox

```python
_VALID_TYPES = [
    "CW_SD_I", "CW_SS_I", "CW_DS_I",
    "FD_SD_I", "FD_SS_I", "FD_DS_I",
    "FD_SD_P", "FD_SS_P", "FD_DS_P",
]
```

`Combobox(values=_VALID_TYPES, state="readonly")`. v1.2 / v1.3
append; nothing else in the combobox logic changes.

#### 3.5.2 New `fmod` field

- Row added between `dr` and `pert`, label `"fmod (MHz)"`, default `100`.
- **Always visible**, **enabled only when** the selected type starts
  with `"FD_"`. Same disabled-grey idiom as `pert` under override.
- `_DEFAULTS["fmod"] = 100.0` (i.e. 100 MHz; 1e8 Hz internally).
- `PARAM_CLASS["fmod"] = "expensive"`.
- Form ↔ physics conversion: GUI stores MHz, `MainWindow.recalculate`
  passes `fmod_hz = values["fmod"] * 1e6` to `make_s_full`. Single
  conversion site at the call boundary.
- Enable / disable wiring lives in `_on_var_changed` next to the
  `pert_override` block: when `type_str` changes, refresh the
  `fmod_entry` state.

This is the **(a)** from the GUI brainstorm — always-visible-and-grey.
Per Q5 lock, when v1.2 lands and a fourth type-specific row appears,
this section migrates to **(c)** (a collapsible "Type-specific
params" group). v1.1 does **not** pre-build (c).

#### 3.5.3 Multi-row `rs` / `rd`

- Labels updated to `"rs [x y z; …] (mm)"` and `"rd [x y z; …] (mm)"`.
- New parser `_parse_float_matrix(text, ncols) -> list[list[float]]`:
  splits on `;`, then each row through the existing
  whitespace/comma split. Empty rows (trailing `;`) are dropped.
  Each row must have exactly `ncols` values.
- `get_values()` returns `rs` and `rd` as `list[list[float]]`
  (was `list[float]`). Top-level `_DEFAULTS["rs"]` / `["rd"]` become
  `list[list[float]]` (single-row).
- `set_values()` formats with `; ` between rows.
- Validation against arrangement happens in `compute.py` (§3.3.2),
  not in the form. The GUI just parses; bad shapes surface via the
  existing `messagebox.showerror("Recalculate failed", str(e))` path.

#### 3.5.4 `MainWindow.recalculate`

Three small changes:

```python
op = _opt_prop_from_dict(values["opt_prop"])
fmod_hz = (
    values["fmod"] * 1e6
    if values["type_str"].startswith("FD_")
    else None
)
result = make_s_full(
    type_str=values["type_str"],
    rs=np.asarray(values["rs"]),     # was np.array([values["rs"]])
    rd=np.asarray(values["rd"]),     # was np.array([values["rd"]])
    opt_prop=op,
    xl=tuple(values["xl"]), yl=tuple(values["yl"]), zl=tuple(values["zl"]),
    dr=values["dr"], pert=tuple(values["pert"]),
    fmod=fmod_hz,
)
```

The extra `np.array([…])` wrapping went away because `rs` / `rd`
are already 2-D from the new parser.

#### 3.5.5 `PARAM_CLASS` updates

```python
"fmod": "expensive",   # changing modulation re-runs physics
```

`pert_override` stays cheap (per fix #1). Everything else unchanged.

#### 3.5.6 `save_data` updates

`np.savez` archive gains one field: `fmod` (Hz, or NaN for CW).
Round-trips via `SensitivityResult.fmod`.

`physics.py` is untouched. `views.py` is untouched.

### 4.2 Module responsibilities

Unchanged from v1; the new dispatch table sits in `compute.py`
because it's the dispatch layer, and the per-entry callables only
import from `physics`. No new files.

### 4.3 Data flow

```
GUI form
  → MainWindow.recalculate
    → make_s_full
      → parse_type_str
      → _expand_optodes(arrangement, rs, rd, z_offset)
        → rSrcs, rDets (shape (N_meas, 3) each)
      → for each measurement i:
          L[i], ll[i], Y[i] = _PHYSICS_DISPATCH[(T, D)](rSrcs[i], rDets[i], …)
      → Svox = _ARRANGEMENT_COMBINE[arrangement](L, Y, ll)
      → S = apply_pert_kernel(Svox, pert, dr)
      → SensitivityResult(...)
    → PlotCanvas.show
```

The physics loop is `N_meas` iterations of vectorized NumPy code;
for v1.1's max `N_meas = 4` (DS), this is ≤ ~2 s on the default
grid. Cheap/expensive split stays as in v1.0.

## 5. MATLAB-fidelity principle

Same as v1: snake_case mirroring, formula structure preserved
line-by-line, regression at `rtol=1e-10` for path-length / fluence,
relax to `rtol=1e-8` for FFT-convolved `S`. The new arrangement
combinators are direct ports of `makeS.m` lines 397–411; the
optode-expansion helper is a direct port of lines 123–149. The
`(temporal, data_type) → (L, ll, Y)` dispatch matches MATLAB's
nested `switch` block.

The existing v1 deviation (`l_vec[z_coords < 0] = 0.0` in
`compute.py`) carries over unchanged — already documented in
v1's review file as an intentional Python-only addition.

## 6. Testing strategy

### 6.1 Numerical fixtures

8 new `.mat` files under `tests/fixtures/`, one per combo:

```
cw_ss_i.mat   cw_ds_i.mat
fd_sd_i.mat   fd_sd_p.mat
fd_ss_i.mat   fd_ss_p.mat
fd_ds_i.mat   fd_ds_p.mat
```

`tests/fixtures/generate_fixtures.m` grows: a small loop calling
`makeS` for each `(type_str, fmod_when_fd)` with the same default
optodes / grid as `cw_sd_i_example1`, writing one `.mat` per
output. Re-run by hand in MATLAB before merge.

`tests/conftest.py` gains a parameterized fixture
`@pytest.fixture(params=[...all combos...])` named `combo_ref` that
re-inflates squeezed shapes the same way as the existing
`cw_sd_i_ref` fixture (uses `np.atleast_1d` on axes, reshapes
`S` / `Svox` to `(Nx, Ny, Nz)`).

### 6.2 Regression tests (one per combo)

```python
def test_make_s_matches_matlab(combo_ref):
    S_py, _ = make_s(**combo_ref["inputs"])
    np.testing.assert_allclose(S_py, combo_ref["S"], rtol=1e-8, atol=1e-12)
```

Tolerances:
- CW combos: `rtol=1e-8` (FFT-conv, same as v1).
- FD `I`: `rtol=1e-8`.
- FD `P`: `rtol=1e-8` (same numerical regime — the imaginary part
  is just another linear combination of the same complex
  exponential / `exp(-mueff·r)` terms).
- Path-length / `Y` intermediates compared at `rtol=1e-10` where
  the fixture exposes them (one fixture per data_type; reused
  across SD / SS / DS to reduce fixture count if the user wants —
  open decision, see §9).

### 6.3 Behavioral tests (no fixtures)

| Test                                                 | Asserts                                                       |
|------------------------------------------------------|---------------------------------------------------------------|
| `test_make_s_rejects_fmod_none_for_fd`               | `FD_SD_I` w/ `fmod=None` → `ValueError`                       |
| `test_make_s_rejects_wrong_optode_shape_for_ss`      | `SS` with `(1,3)+(1,3)` → `ValueError("Incorrect optode...")` |
| `test_make_s_rejects_wrong_optode_shape_for_ds`      | `DS` with `(1,3)+(2,3)` → `ValueError`                        |
| `test_expand_optodes_ds_meas_order`                  | rows match MATLAB `[rs1,rs1,rs2,rs2]×[rd1,rd2,rd2,rd1]`       |
| `test_parse_float_matrix_semicolon`                  | `"0 0 0; 30 0 0"`, trailing `;`, mixed whitespace             |
| `test_parameter_panel_handles_multi_row_rs_rd`       | round-trip set/get on a 2-row `rs`                            |
| `test_main_window_recalculates_fd_sd_i`              | GUI-level smoke against one FD fixture                        |
| `test_old_session_json_loads_into_v1_1`              | v1-shaped session JSON loads; new fields use defaults         |
| `test_fmod_field_disabled_when_type_is_cw`           | toggling type combobox updates `fmod_entry` state             |
| `test_param_class_classifies_fmod_as_expensive`      | `PARAM_CLASS["fmod"] == "expensive"`                          |

**Coverage target:** every new combo has at least one regression
test against MATLAB. Every new public-API failure path has at
least one behavioral test.

## 7. Migration & backwards compatibility

### 7.1 Old `last_session.json`

No code change needed. Verified by inspection (test
`test_old_session_json_loads_into_v1_1` covers it):

- Old session has no `fmod` key → `set_values` skips it (per fix #9
  permits missing keys) → form keeps `_DEFAULTS["fmod"] = 100.0`.
- Old `rs` / `rd` were single-row `"0 0 0"` → `_parse_float_matrix`
  returns `[[0.0, 0.0, 0.0]]`, exactly what the v1.1 dispatch
  expects for `CW_SD_I`.

### 7.2 Old user code calling `make_s_full`

`make_s_full(type_str="CW_SD_I", rs=[[0,0,0]], rd=[[35,0,0]], …)`
returns a byte-identical `SensitivityResult.S` to v1.0 (regression
asserted by the existing fixture). New `Y_per_meas` and `fmod`
fields are kw-only via `field(kw_only=True)` so positional
construction in tests still works.

### 7.3 Old `.npz` data archives

`save_data` archive grows by one field (`fmod`). Loading a v1.0
archive still works (no migration needed; `fmod` simply isn't
present and consumers know to skip it). `load_data` is not in
scope for v1.1.

## 8. Extension points for v1.2 / v1.3 / v2.0

**v1.2 (TD GI)** lands as:
- New `physics.py` functions: `temporal_fluence`,
  `temporal_reflectance`, `temporal_gate_tot_path_len`,
  `temporal_gate_part_path_len`. (At this point `physics.py` likely
  crosses 500 lines; per v1's spec §8 it splits into a
  `physics/` subpackage.)
- New `_PHYSICS_DISPATCH` entries: `("TD", "GI")`. No combinator
  changes needed.
- New GUI rows: `tg [t_lo t_hi] (ns)`, `tend (ns)`, `ndt`. At this
  point the type-specific params group migrates from (a)
  always-visible-and-grey to (c) collapsible group, per the
  v1.1 brainstorm.

**v1.3 (TD DGI / T / V)** lands as:
- More physics: `temporal_kth_mom_*`, `temporal_var_*`,
  `temporal_kth_moment`, `temporal_var`.
- Three more dispatch entries: `("TD", "DGI")`, `("TD", "T")`,
  `("TD", "V")`. The `T` and `V` entries return non-trivial `Y`
  (the measured signal itself), exercising the `Y_per_meas`
  plumbing introduced in v1.1.
- New combinator: `_combine_sd_diff` (used internally by DGI).
- New GUI row: `tgE [t_lo t_hi] (ns)`.

**v2.0** is the audit / docs / cleanup release: full README rewrite
of the supported matrix, regenerate the screenshot, sweep through
CLAUDE.md, optionally retire the cheap/expensive split if all of
TD turns out fast enough.

## 9. Deferred / open decisions

1. **Fixture reuse across arrangements.** §6.2 currently lists 8
   fixtures (one per combo). An alternative is one fixture per
   `(temporal, data_type)` (3 total: CW_I, FD_I, FD_P) plus three
   tiny `(L, Y, ll)` fixtures verifying the SS / DS combinators
   independently. This trades MATLAB regen time for slightly more
   complex tests. **Recommended decision: keep 8 per-combo
   fixtures** for v1.1 — matches v1.0's pattern, no novelty in the
   test scaffolding.

2. **Default optodes for SS / DS.** The GUI's `_DEFAULTS["rs"]` /
   `["rd"]` are single-row. When a user picks `SS` / `DS` the form
   needs more rows — currently triggers a recalc error. Could
   auto-fill with a second row (`+10 mm` along x) on type change.
   **Recommended decision: leave alone for v1.1** (error message
   will say `"Incorrect optode count for arrangement 'SS'..."`).
   Revisit at v2.0 polish.

3. **`SensitivityResult.fmod` for CW combos.** `None` vs `0.0` vs
   `np.nan`. The spec sets `None`; `save_data` writes `np.nan` to
   the archive (NumPy doesn't accept `None` in `np.savez`).
   **Recommended decision: as written.**
